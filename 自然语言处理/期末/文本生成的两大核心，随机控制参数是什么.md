在以 Transformer 解码器（Decoder）为基础的文本生成任务（如 GPT 系列或各种大语言模型）中，模型在预测下一个词时，会输出整个词表大小的原始得分（Logits）。

为了控制模型从这些得分中“挑选”下一个词的随机性和创造力，业界最核心的两个控制参数是 **Temperature（温度）** 和 **Top-p（核采样）**。

我们结合之前讨论过的 Logits 和 Softmax，从底层数学逻辑来看看这两个参数是怎么起作用的：

### 1. Temperature (温度参数)

**核心作用：在 Softmax 阶段改变概率分布的“平缓度”。**

在标准的神经网络中，我们将 Logits（原始得分向量 $Z$）转化为概率分布使用的是标准 Softmax。而引入 Temperature（通常用 $T$ 表示）后，公式变成了这样：

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

通过调整分母上的 $T$，我们可以直接拉伸或挤压概率分布：

- **$T \to 0$ (极低温度，如 0.1)：**
    
    此时得分高的词，其概率会被无限放大，逼近于 1。这相当于退化成了贪婪搜索（Greedy Search，即直接使用 `argmax`）。模型输出会变得极其确定、严谨，但也容易陷入机械重复。适合于代码生成、数学计算或事实问答。
    
- **$T = 1$：**
    
    标准 Softmax 状态，模型按训练时学到的原始概率进行采样。
    
- **$T > 1$ (高温度，如 0.8 或更高)：**
    
    此时所有得分的差异被缩小，原本概率极低的“生僻词”也有了出场机会，整个概率分布变得更加平缓（趋于均匀分布）。模型会表现出极强的发散性、创造力，但也容易产生“幻觉”或胡言乱语。
    

### 2. Top-p (核采样 / Nucleus Sampling)

**核心作用：在计算完概率后，动态“截断”候选词表。**

如果我们只用 Temperature，即使是很不合理的词，依然有微小的概率被选中。为了避免模型在发散时彻底跑偏，Top-p 充当了一把**动态的概率剪刀**。

它的执行逻辑如下：

1. 首先，将词表中所有词的预测概率从大到小排序。
    
2. 然后，从概率最大的词开始往下累加，一旦**累加的概率总和刚好超过设定的阈值 $p$**，就立刻停止。
    
3. 被圈进来的这部分词组成了一个“核心候选池”（Nucleus），而剩余的所有词的概率被强制清零。
    
4. 最后，将候选池里的词重新进行一次概率归一化，从中随机抽取下一个词。
    

**参数效果：**

- **低 $p$ 值 (如 0.1)：** 累加极快，可能只圈进去了 1 到 2 个概率最高的词，相当于极其保守的截断。
    
- **高 $p$ 值 (如 0.9)：** 允许大量长尾的候选词保留在池子里，保持了采样的丰富度，同时只砍掉最离谱的那 10% 的极其不合理的词。
    

### 💡 它们在实际代码中的配合使用

这两个参数通常是**协同工作**的。在很多 PyTorch 的生成脚本或者大模型 API 的调用中，执行顺序永远是：**先用 Temperature 调整分布，然后再用 Top-p 进行截断。**

- **想写严谨的技术报告 / 提取结构化数据：**
    
    设置 `Temperature = 0.1` 左右，`Top-p = 0.1`，甚至直接屏蔽随机性。
    
- **想写小说 / 头脑风暴：**
    
    设置 `Temperature = 0.8` 以上，`Top-p = 0.9` 左右。这样既能保证用词的多样性和惊喜感（高 T），又用 Top-p 兜底，防止模型生成完全不讲语法的乱码。
