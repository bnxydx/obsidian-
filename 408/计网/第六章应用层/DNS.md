domain name system
域名系统

DNS作用：把域名转化成ip

---

> **DNS（Domain Name System，域名系统）** 是因特网使用的命名系统，将便于记忆的域名转换为机器可处理的 IP 地址，采用 C/S 模型，协议运行在 **UDP 53 号端口**。

- DNS 从概念上分为三部分：**层次域名空间**、**域名服务器**、**解析器**

特点：
1. 使用C/S工作方式
2. 是应用层协议
3. 分布式系统，计时单个计算机出问题，不会影响运行

# 层次域名空间

> 因特网采用**层次树状结构**的命名方法，每个域名由标号序列组成，标号之间用 "." 隔开，级别最低在左、最高在右。

- **标号规则**（考点）：
  - 英文不区分大小写
  - 除连字符 `-` 外不能使用其他标点符号
  - 每个标号（两个点之间的字母或数字 ） **≤63 字符**，完整域名总长 **≤255 字符**
  - 级别最低的域名写在最左边，顶级域名在最右边
- **顶级域名（TLD）三大类**：
  - **国家（地区）顶级域名（nTLD）**：如 `.cn`、`.us`、`.uk`
  - **通用顶级域名（gTLD）**：如 `.com`、`.net`、`.org`、`.edu`、`.gov`
  - **基础结构域名（arpa）**：用于 **反向域名解析**（IP → 域名）


> 域名层次结构呈"**顶级域 → 二级域 → 三级域 → …**"的倒置树状，每一级域名由上一级授权管理。以 `www.csksoyan.com` 为例：**`com` 为顶级域名、`csksoyan` 为二级域名、`www` 为三级域名**（图 6.3，王道教材）。

- **域名层次递进关系**：域（Domain）是名字空间中可被管理的划分，**域可划分为子域，子域可继续划分为子域的子域**，由此形成顶级域、二级域、三级域等层次
- **上级授权原则**：每一级域名的分配和管理权属于其**直接上级域**的所有者（如 `.com` 的管理者授权 `csksoyan` 二级域，`csksoyan` 的所有者再自行分配 `www` 等三级域名）


> **顶级域名（TLD）** 处于域名空间的最顶层，由 **ICANN（互联网名称与数字地址分配机构）** 统一管理。

- **管理权限**：ICANN 负责 TLD 的分配与管理，决定新增或撤销 TLD；各 TLD 注册管理机构（Registry）负责具体运营（如 Verisign 运营 `.com` 和 `.net`）
- **三大类补充说明**：
  - **国家顶级域名ccTLD**：如 `.cn`（中国）、`.jp`（日本）、`.kr`（韩国），由国家/地区自行管理
  - 通用顶级域名**gTLD**：`.com`（公司）、`.net`（网络服务）、`.org`（非营利组织）、`.edu`（仅限美国教育机构）、`.gov`（仅限美国政府）、`.mil`（美国军事）、`.int`（国际组织）
  - **基础结构域名arpa**：专门用于反向解析的**特殊域**，将 IP 地址映射回域名时使用 `in-addr.arpa`（IPv4）或 `ip6.arpa`（IPv6）
- **新通用顶级域（New gTLD）**：2012 年起 ICANN 开放，如 `.app`、`.blog`、`.shop`、`.xyz` 等


> **二级域名** 是在 TLD 下注册的域名，是**组织或个人在互联网上的唯一标识**。

- **定义与举例**：在 `csksoyan.com` 中，`csksoyan` 即为二级域名；在 `tsinghua.edu.cn` 中，`edu` 是 `.cn` 下的二级域名
- **管理权限**：
  - 二级域名由对应的**顶级域名注册管理机构**授权分配
  - 二级域名所有者获得该域名的**自主管理权**，可自行在该二级域名下创建三级及更低级域名
  - 每个二级域名需在对应的**权限域名服务器**中注册登记
- **命名规则**：同标号规则（≤63 字符、仅字母数字连字符、不区分大小写）
- **考点**：国家代码顶级域（如 `.cn`）下的二级域名也分**类别域名**（如 `.com.cn`、`.edu.cn`、`.gov.cn`）和**行政区域域名**（如 `.bj.cn` 北京、`.sh.cn` 上海），两者均属于 `.cn` 的二级域名


> **三级域名** 是二级域名下由域名所有者自行划分子域的结果，用于标识具体的主机或服务。

- **定义与举例**：在 `www.csksoyan.com` 中，`www` 为三级域名；在 `mail.tsinghua.edu.cn` 中，`mail` 为三级域名（`tsinghua` 为四级）
- **管理权限**：
  - 三级域名由**二级域名（或上级域）的所有者**自行分配，无需向 ICANN 或注册管理机构申请
  - 可在权限域名服务器中为每个三级域名添加相应的 **A 记录**或 **CNAME 记录**
- **常见三级域名用途**：
  - `www`：提供 Web 服务（可使用 CNAME 指向实际服务器）
  - `mail`：邮件服务器
  - `ftp`：文件传输服务
  - `blog` / `news` / `api` 等：按业务功能划分
- **命名规则**：同标号规则，由二级域名所有者自由命名

# 域名服务器
> 域名解析由分布在因特网上的大量域名服务器按层次协作完成，没有一台服务器拥有全部映射。
![](Pasted%20image%2020260805091549.png)
- **区（Zone）**：域名服务器管辖的范围，区 ≤ 域，一个区中所有节点必须连通
- 4 种类型域名服务器：

| 类型               | 核心职责                                       | 考点                                          |
| ---------------- | ------------------------------------------ | ------------------------------------------- |
| **根域名服务器**       | 知道所有顶级域名服务器的 IP；不直接解析域名，而是**告诉本地服务器下一步找谁** | 全球 **13 个**根服务器（实际是集群，非物理单台）                |
| **顶级域名服务器（TLD）** | 管理其下所有二级域名，返回相应权限服务器的地址                    | 如 `.com` 服务器管理所有 `.com` 域名                  |
| **权限域名服务器（授权）**  | 负责将其**管辖的主机名直接转换为 IP 地址**（最终查询终点）          | 每台主机必须登记；常同时充当本地和权限服务器                      |
| **本地域名服务器**      | 离用户最近，**主机发出的 DNS 查询首先发往本地域名服务器**          | ISP / 大学 / 系可各自拥有；Windows 配置的 DNS 地址即本地 DNS |
一台主机内部也有DNS缓存

# 域名解析

> 域名解析有 **递归查询** 与 **迭代查询** 两种方式，实际中递归 + 迭代混合使用。

### 递归查询

- 主机 → 本地域名服务器：**默认采用递归查询**
- 若本地不知道，则**替主机逐级向上查询**，中间结果不返回主机，直到拿到最终 IP 或失败才返回
- 本地 -> 根域名服务器 -> 顶级域名 -> 权限域名
![](Pasted%20image%2020260805094526.png)

### 迭代查询

- 本地域名服务器 → 根 / TLD / 权限服务器：**通常采用迭代查询**
- 每级返回下一级的地址（"我不知道，但你可以去问 XXX"），本地域名服务器**依次自己去问**
- 命题追踪：迭代查询的工作原理（2016、2020）
- **根域名服务器收到迭代查询时**：要么给出 IP，要么告知下一步应向哪个顶级域名服务器查询
- 告诉你要去找谁，给你ip让你自己找
![](Pasted%20image%2020260805094755.png)

### 完整解析过程示例（最多 8 个 UDP 报文）

> 客户机想获知 `y.abc.com` 的 IP 地址：

| 步骤 | 动作 | 查询类型 |
|------|------|----------|
| 1 | 客户机 → 本地域名服务器发出 DNS 请求 | **递归** |
| 2 | 本地查缓存无结果 → 向根域名服务器发出请求 | **迭代** |
| 3 | 根 → 返回 `dns.com`（.com 顶级服务器）地址 | — |
| 4 | 本地 → `dns.com` 发出请求 | **迭代** |
| 5 | `dns.com` → 返回 `dns.abc.com`（权限服务器）地址 | — |
| 6 | 本地 → `dns.abc.com` 发出请求 | **迭代** |
| 7 | `dns.abc.com` → 返回 `y.abc.com` 的 IP | — |
| 8 | 本地域名服务器**缓存结果**并返回给客户机 | — |

- **易混淆点**：主机到本地 = 递归，本地到根/TLD/权限 = 迭代；**递归给根服务器造成负载过大，实际几乎不用**

---

> **DNS 高速缓存**广泛用于域名服务器和主机，以提高查询效率、减少 DNS 报文数量。

- **域名服务器缓存**：缓存最近查询过的域名映射，TTL 到期后自动丢弃（因为映射不是永久的）
- **主机缓存**：许多主机启动时从本地域名服务器下载数据库，维护最近使用域名的缓存；缓存未命中时才使用域名服务器
- **时效性问题**：权限服务器中的映射变更后，缓存中旧记录在 TTL 到期前不会更新
