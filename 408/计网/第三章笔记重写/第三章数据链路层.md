# 第三章 数据链路层（408 重写版）

> 本章主线：**数据链路层以「帧」为单位**，解决相邻结点之间在一段物理链路上可靠、高效地传输数据的问题。核心考点集中在：组帧方法、差错控制（CRC / 海明码）、可靠传输协议（SW / GBN / SR）、介质访问控制（CSMA/CD、CSMA/CA）、以太网帧格式、交换机与 VLAN。

---

## 3.1 功能与基本概念

### 3.1.1 链路 vs 数据链路

| 概念 | 含义 |
| ---- | ---- |
| **链路（Link）** | 从一个结点到相邻结点的一段物理线路，中间没有任何其他交换结点 |
| **数据链路（Data Link）** | 在链路上加上实现通信协议的**硬件和软件**后构成的逻辑链路 |

- 数据链路层传输与处理的单位是**帧（Frame）**：给网络层下发的分组（IP 数据报）添加帧头、帧尾封装而成。
- 数据链路层建立在**物理层之上**，物理层提供原始比特流，数据链路层负责把比特流划分为帧并保证帧的正确交付。

### 3.1.2 数据链路层的主要功能

1. **封装成帧（组帧）**：添加帧头帧尾，实现帧定界，对上层透明；
2. **透明传输**：不论数据部分是什么比特组合，都能原样无差错地在链路上传输，处理「数据中出现定界符」的误判问题；
3. **流量控制**：限制发送方发送速率，使其不超过接收方的接收能力；
4. **差错检测（差错控制）**：检错码 / 纠错码发现或纠正传输错误；
5. **可靠传输**：通过确认 + 超时重传，解决帧丢失、帧重复、帧失序；
6. **介质访问控制**：协调广播信道上多个结点对共享信道的使用（点对点信道通常不需要）。

> **考点提示**：数据链路层的功能是选择题高频。注意区分「流量控制」「差错控制」「可靠传输」各自解决什么问题。

### 3.1.3 两类信道下的问题

- **点对点信道**（如 PPP 链路）：
  - 封装成帧（帧定界）、差错检测、可靠传输；
  - 不需要地址（点对点，接收方唯一）。
- **广播信道**（如传统以太网总线）：
  - 需要**目的地址（MAC 地址）** 判断帧是否发给本结点；
  - 多结点同时发送会产生**帧碰撞** → 需要介质访问控制（CSMA/CD），现代用**交换机**实现交换式以太网消除碰撞。

### 3.1.4 数据链路层 vs 传输层的流量控制

| 对比维度 | 数据链路层 | 传输层 |
| ---- | ---- | ---- |
| 控制范围 | **相邻结点之间** | **端到端** |
| 控制手段 | 接收方接收不了时不返回确认帧 | 确认报文段中携带窗口字段，动态调整发送窗口 |
| 窗口大小 | 传输过程中**固定** | **动态调整** |

> OSI 体系下流量控制在数据链路层；TCP/IP 体系下流量控制上移到传输层。**同一帧的发送窗口大小在传输过程中不变**（与传输层不同）。

## 3.2 组帧（封装成帧）

### 3.2.1 基本概念

- **帧定界**：确定一帧的开始与结束；
- **帧同步**：接收方能成功识别出帧的开始和结束；
- **MTU（最大传送单元）**：帧的数据部分长度的上限。

### 3.2.2 四种组帧方法

| 方法 | 原理 | 优点 | 缺点 / 要点 |
| ---- | ---- | ---- | ---- |
| **字符计数法** | 帧首部用定长计数字段标明帧长 | 实现简单 | 计数字段一旦出错，**后续所有帧都无法定界** |
| **字节填充法（字符填充）** | 用 SOH、EOT 标记帧首尾，数据中出现定界符时插入**转义字符** | 解决透明传输 | 开销随数据中定界符数量增加 |
| **零比特填充法** | 用特殊比特串（如 01111110）定界；发送方遇 **5 个连续 1 插入一个 0**，接收方见 5 个 1 删掉后面的 0 | 用于 **HDLC、PPP** 同步线路 | 硬件实现简单 |
| **违规编码法** | 借用物理层编码的「违规信号」定界（如曼彻斯特编码中「中间不跳变」） | 不增加额外开销 | 需要**物理层配合** |

> **透明传输的本质**：数据部分出现与定界符相同的比特组合时，不能让接收方误判为边界。字节填充处理 0x7E / 0x7D 时采用「转义符 + 原字节异或 0x20」：`0x7E → 0x7D 0x5E`，`0x7D → 0x7D 0x5D`。

## 3.3 差错控制

### 3.3.1 差错分类

- **位错（比特差错）**：帧内某一位或多位出错 → 用**检错码**（发现并丢弃重传）或**纠错码**（发现并纠正）处理；
- **帧丢失 / 帧重复 / 帧失序**：→ 用**确认 + 重传**的可靠传输机制处理。

### 3.3.2 奇偶校验码（检错）

- 添加 1 位校验位，使整个码字中 1 的个数为奇数（**奇校验**）或偶数（**偶校验**）；
- 校验：把所有位异或，偶校验结果应为 0，奇校验结果应为 1；
- 只能检出**奇数个**位错，无法定位错误，检测能力有限。

### 3.3.3 循环冗余校验 CRC（重点）

**基本思想**：发送方用生成多项式 `G(x)` 对信息位做模 2 除法，把余数（FCS 帧检验序列）附在数据后；接收方同样做除法，**余数为 0 则无差错，非 0 则丢弃该帧**。

**计算步骤（以 G(x)=x³+x²+1，信息码 101001 为例）**：
1. 生成多项式对应除数：`1101`，校验位数 r = 3；
2. 信息码左移 r 位补 0：`101001000`（被除数）；
3. 被除数与除数做**模 2 除法（异或）**，得到余数 `001`；
4. 余数拼回信息码尾部，得 CRC 码：`101001001`。

**考点细节**：
- CRC 是**检错编码**，检错能力很强（漏检率极低），但**一般不用来纠错**（余数虽可指示某位错，但多位错时可能无法区分，如图示 1 与 8 位错误余数相同）；
- CRC 检错：**能发现错误但不知道哪一位错**，出错帧直接丢弃、由可靠传输机制重传；
- 生成多项式的最高位通常为 1，r 位生成多项式对应 r 位校验码。

### 3.3.4 海明码（纠错编码，重点）

**前置概念——码距（海明距离）**：两个等长码字之间不同位的个数；一个编码方案的最小码距决定其检错/纠错能力。

**海明码原理**：
- 在 n 个信息位中插入 **k 个校验位**，把信息位划分为 k 个分组，每组由 1 个校验位负责；
- 校验位个数满足：**`2^k ≥ n + k + 1`**（k 位校验位的 `2^k` 种状态要能表示「无错 + n+k 位中任意一位出错」）；
- 规定：**校验位放在 `2^(i-1)` 号位置**（第 1、2、4、8…位）；
- 接收方按位置分组依次异或，得到的**指错字**指明出错位置，取反即可纠错；
- 增加**全校验位**做整体偶校验，可区分 1 位错与 2 位错。

**能力**：海明码 **1 位纠错、2 位检错**。

### 3.3.5 码距与检错 / 纠错能力（高频结论）

设编码最小码距为 d：
- 检测 e 个位错：**`d ≥ e + 1`**；
- 纠正 t 个位错：**`d ≥ 2t + 1`**；
- 同时检 e 个、纠 t 个（e > t）：**`d ≥ e + t + 1`**。

> 例：检 1 位错最小码距 2；纠 1 位错最小码距 3。偶校验码码距为 2，只能检 1 位错、不能纠错。

## 3.4 流量控制与可靠传输机制

### 3.4.1 流量控制

**流量控制**：由**接收方**控制发送方的发送速率，防止发送过快淹没接收方。两种实现思路：
1. **停止-等待协议**：发一帧等一确认，简单但利用率低；
2. **滑动窗口协议**：发送方维持**发送窗口**（可连续发送的帧序号集合），接收方维持**接收窗口**（允许接收的连续帧序号，超范围帧丢弃）；收到确认后窗口后移。

### 3.4.2 可靠传输与 ARQ

**可靠传输**：确保发送方发出的数据被接收方正确且完整接收。核心机制：
- **确认（ACK）**：每成功收到一帧返回确认帧；
- **超时重传**：启动计时器，超时未收到确认则重传（**发送方自主触发**，无需接收方显式请求）；
- 数据帧与确认帧**都要编号**以标识对应关系。

帧头帧尾中的控制信息包括：帧定界信息、校验码、帧类型（数据帧 / 确认帧）、帧序号。

> **ARQ（自动重传请求）**：结合确认与超时重传的可靠传输协议统称。三种 ARQ 协议（SW / GBN / SR）不仅适用于数据链路层，也适用于传输层。
>
> **实际应用**：有线网络误码率低，数据链路层一般不提供可靠传输（交给上层端到端处理）；无线网络误码率高，数据链路层必须提供可靠传输。

### 3.4.3 三种协议对比（核心考点）

| 协议 | 发送窗口 W_T | 接收窗口 W_R | 确认方式 | 出错处理 | 帧编号位数 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| **停止-等待（SW）** | 1 | 1 | 逐帧确认 | 重传当前帧 | 1 bit（0/1 即可判重复） |
| **后退 N 帧（GBN）** | `1 < W_T ≤ 2^n - 1` | **1**（只按序接收） | **累计确认** | 重传出错帧及**其后所有已发送未确认的帧** | n bit |
| **选择重传（SR）** | `1 < W_T ≤ 2^n - 1` | `1 < W_R ≤ W_T` | **逐帧确认（不支持累计）** | 仅重传出错/超时的那一帧 | n bit |

**窗口约束（n 比特编号，硬核考点）**：
- 条件①：**`W_T + W_R ≤ 2^n`**（否则序号空间不足，确认丢失后重传的旧帧序号可能与新帧重叠，接收方无法区分）；
- 条件②：**`W_R ≤ W_T`**（接收窗口大于发送窗口时资源浪费）；
- 由①②推导：**`W_R ≤ 2^(n-1)`**；实践中常取 `W_R = W_T = 2^(n-1)`。

**协议细节**：
- **SW**：发送窗口 = 接收窗口 = 1，一发一等；数据帧、确认帧出错或丢失都需要重传；仅需 1 bit 编号判断重复帧。
- **GBN**：发送方可在未确认时连续发送窗口内多个帧；接收方**仅按序接收，任何失序帧一律丢弃**；**累计确认**：连续收到多个正确帧后只需对其中序号最大的帧发 ACK（如收到 0、1、2 号帧，回 ACK2 表示 2 号及之前全部正确）；某帧超时 → 重传该帧及其后所有未确认帧。
- **SR**：接收方必须能**暂存失序但正确、序号仍在接收窗口内**的帧；发送方为每个未确认帧维护**独立计时器**，超时仅重传该帧；收到重复帧（说明 ACK 丢失）则丢弃并重传对应 ACK；可用 **NAK（否认帧）**：接收方检测到 i 号帧出错 → 丢弃并回 NAK_i → 发送方立即重传 i 号帧。

### 3.4.4 信道利用率（计算考点）

**发送周期**（一帧从开始发送到收到其确认所需时间）：
$$
T = t_1 + 2\tau + t_2
$$

**信道利用率**：
$$
U = \frac{k \cdot t_1}{t_1 + 2\tau + t_2}
$$

| 参数 | 含义 |
| ---- | ---- |
| k | 发送窗口大小（连续发送帧数） |
| t_1 | 发送一帧的传输时间 = 帧长 / 传输速率 |
| t_2 | 确认帧传输时间 |
| τ | 单向传播时延 |

**特例**：
- 忽略确认帧传输时间：t₂ = 0；
- 停止-等待：k = 1；
- GBN：k ≤ 2ⁿ − 1；SR：k = 2ⁿ（实际受窗口约束）。

> 例：t₁ = 4，τ = 7，t₂ = 1 时 SW 的利用率 = 4 / (4 + 14 + 1) ≈ 21%。GBN/SR 主要取决于发送窗口大小，窗口足够大时利用率可接近 100%。

## 3.5 介质访问控制 MAC（重点章节）

**目标**：协调共享同一广播信道的多个结点，避免信号冲突（冲突会导致信号干扰、通信失败）。分类：

| 大类 | 方式 | 特点 |
| ---- | ---- | ---- |
| **信道划分** | TDM / FDM / WDM / CDM(CDMA) | 静态划分，逻辑上将广播信道分成互不干扰的子信道，**不会冲突** |
| **随机访问** | ALOHA / CSMA / CSMA-CD / CSMA-CA | 动态争用，结点随机发送，可能冲突，靠协议解决 |
| **轮询访问** | 轮询 / 令牌传递 | 动态分配，结点轮流使用信道，**不冲突** |

### 3.5.1 信道划分介质访问控制（静态）

核心是**复用（Multiplexing）**：发送端把多个信号组合到一条物理信道，接收端分离还原。

| 方式 | 原理 | 说明 |
| ---- | ---- | ---- |
| **频分复用 FDM** | 按**频率**划分不同频带，同时传输 | 各路信号互不干扰 |
| **时分复用 TDM** | 按**时间**划分时隙，轮流占用 | 各站点按固定时间片发送 |
| **波分复用 WDM** | 在一根光纤中传输不同**波长**的光信号 | 光的频分复用，用于光纤 |
| **码分复用 CDM / 码分多址 CDMA** | 各结点分配**正交的码片序列**，叠加传输后靠内积分离 | 主要用于多址接入，是近年高频考点 |

**CDMA 要点（计算/概念考点）**：
- 每个结点分配专属**码片序列**，取值 1 或 −1；发比特 1 发码片本身，发比特 0 发码片的反码（−1 序列）；
- 各站点码片序列**两两正交**：不同码片内积为 0，自身内积为 1（归一化）；
- 接收方将收到的**叠加信号**与目标站码片做**内积**：结果为 **1 → 发送方发 1**，**−1 → 发 0**，**0 → 未发送**；
- 所有站点**同时发送**，信号在信道中线性叠加，接收端靠码片正交性分离出各路数据。

### 3.5.2 随机访问介质访问控制（动态）

#### ① ALOHA 协议

| 协议 | 规则 | 特点 |
| ---- | ---- | ---- |
| **纯 ALOHA** | **不听就发**：要发立即发，不检测信道；未收到确认 → 等**随机时间**重发 | 冲突概率高，信道利用率低 |
| **时隙 ALOHA** | 时间划分为等长**时隙**，所有站点同步；只能在**时隙起始**发送，一帧发送时间 ≤ 时隙长度 | 冲突减半，利用率约为纯 ALOHA 的两倍 |

> 两者冲突率都太高，因此引入「先听后发」的 CSMA 思想。

#### ② CSMA 协议（载波监听多路访问）

**做法**：发送前先监听信道是否空闲，空闲才发送（网卡上安装载波监听装置）。

| 类型 | 信道空闲 | 信道忙 | 特点 |
| ---- | ---- | ---- | ---- |
| **1-坚持** | 立即发送 | 一直监听，一空就发 | 空闲即发冲突概率高（大家都等着，同时发送） |
| **非坚持** | 立即发送 | 等一个**随机时间**再监听 | 冲突减少但平均传输时延增加 |
| **p-坚持** | 以**概率 p** 发送，1−p 推迟到下一时隙 | 等到下一时隙再监听 | 时隙化，兼顾冲突与时延 |

#### ③ CSMA/CD（载波监听多路访问 / 碰撞检测）—— 重点

**适用**：传统总线型以太网（同轴电缆、集线器组成的逻辑总线），**有线、半双工**。

**工作流程**：先听后发 → 边听边发（发送同时检测冲突）→ 冲突停发 → 随机重发。

**争用期（碰撞窗口）**：`2τ`（τ 为最大单向传播时延）。
- 发送方最多经过 **2τ** 才能确定检测到碰撞（最坏情况）；
- **争用期内未检测到冲突 → 该帧不会再冲突，发送成功**；
- CSMA/CD **没有确认机制**，未检测到冲突即视为发送成功。

**最短帧长（高频计算考点）**：
$$
\text{最短帧长} = 2\tau \times \text{信道带宽}
$$
- 原因：帧发送时间必须 ≥ 争用期，否则发完才知冲突，发送方误判成功不再重传；
- 10Mbps 以太网：争用期 51.2μs → 最短帧长 **512 bit = 64 B**；帧长不足 64B 需填充；
- 最长帧长：1518B（防止某结点一直占用信道）。

**截断二进制指数退避算法**：
- 以**争用期 2τ** 为基本退避单位；
- 第 k 次重传：从 `[0, 2^k − 1]` 随机取 r，推迟 `r × 2τ`；
- k = min(重传次数, 10)，前 10 次窗口指数增长，之后恒为 [0, 1023]；
- 思想：冲突越多 → 退避窗口越大 → 连撞概率越低；
- **连续 16 次失败 → 放弃该帧，向高层报错**。

> 考点：争用期 2τ、最短帧长公式、64B/1518B、16 次上限、退避窗口变化。

#### ④ CSMA/CA（载波监听多路访问 / 碰撞避免）—— 重点

**适用**：IEEE 802.11 无线局域网（WiFi）。

**为什么无线不用 CSMA/CD**：
- 无线信号传播中强度衰减，站点不一定都能互相监听（存在**隐蔽站**问题），**无法可靠检测冲突**；
- 因此无线采用**冲突避免（CA）**：发送前尽量避让，而不是边发边检测。

**帧间间隔 IFS（三种）**：
- **DIFS**（最长）：每帧事务开始前需要等待的时间；
- **PIFS**（中等）；
- **SIFS**（最短）：收到一个帧后预留的处理时间（ACK 等用）。

**工作原理**：
1. **先听后发，忙则退避**：信道空闲则等随机时间后发送；信道忙则随机退避；
2. **随机退避**：采用二进制指数退避确定退避时间；发送方持续监听，**只有信道空闲才扣除倒计时**，计时结束立即发送；
3. **停止-等待式确认**：接收方每收到一个正确帧都返回 ACK，发完一帧收到确认才能继续。

**虚拟载波监听（NAV）**：
- A 向 B 发送时在帧首部「持续期」字段写入占用信道总时长；
- 其他站点收到后设置**NAV（网络分配向量）**，倒计时期间**暂停发送**；
- 效果等同持续监听信道 → 降低冲突概率，解决隐蔽站检测不到碰撞的问题。

**信道预约（RTS/CTS，解决隐蔽站）**：
1. DIFS → 发送方发 **RTS**（控制帧：源地址、目的地址、持续时间）预约信道；
2. SIFS → 接收方回 **CTS**（广播，允许发送），其他站收到后设置 NAV 不再发送；
3. SIFS → 发送数据帧 → SIFS → ACK。

> **隐蔽站**：因信号覆盖范围受限或障碍物遮挡，彼此无法检测到对方存在的结点（如 A 与 C 都在 AP 覆盖内但互相听不到），可能同时向 AP 发送造成冲突；RTS/CTS 预约机制解决此问题。

### 3.5.3 轮询访问介质访问控制（动态）

- **轮询协议**：主结点轮流询问各从结点是否发送，从结点被问到才可发；主结点故障则全网瘫痪；
- **令牌传递协议**：一个**令牌**在环形网络中传递，**拿到令牌才能发送数据**，发完释放令牌（重新生成令牌帧），每次只能传一个数据帧；
- 特点：不冲突、效率高，**更适用于重负载**情况（轻负载时轮询开销大、时延高）。

## 3.6 局域网

### 3.6.1 局域网概述

**定义**：较小物理范围内，通过传输介质（双绞线、同轴电缆、光纤等）互连计算机与外部设备，实现高速、低时延、**广播/多播**通信。

**特点**：
1. 通常为一个单位所有，地理范围与站点数量有限；
2. 共享较高总带宽（较高数据传输速率）；
3. 低传输时延、低误码率；
4. 各站点地位平等，无主从关系；
5. 支持单播、广播、多播。

**分类**：以太网（总线结构，CSMA/CD）、令牌环（环状）、FDDI 光纤分布式数字接口（环状）。

### 3.6.2 以太网与 IEEE 802.3

**传输介质发展**：
- **10Base5**：同轴电缆，只支持半双工；
- **10Base-T**：双绞线 + 集线器（星型但逻辑上仍是总线，需 CSMA/CD）；或双绞线 + **交换机**（真正星型，全双工可不用 CSMA/CD）；
- **10Base-F / 光纤以太网**：点对点，两条光纤全双工，用于中继器、集线器、交换机之间。

**以太网标准参数（802.3）**：
- 最短帧长：**64B（512 bit）**；最长帧长：**1518B**；
- 10BASE-T 争用期：**51.2μs**；100BASE-T 争用期：**5.12μs**；
- 帧间最小间隔：9.6μs（信道空闲且持续 ≥ 9.6μs 才开始发送）。

### 3.6.3 网卡（网络适配器）

- 计算机与局域网连接通过主板上的**网络适配器（Adapter / 网卡）** 实现；内含处理器与存储器，工作在**数据链路层**；
- 适配器与局域网通过电缆以**串行**方式通信，与计算机通过 IO 总线**并行**通信，需支持帧缓存；
- 功能：物理连接与电信号匹配、帧发送/接收、帧封装/拆封、介质访问控制、数据编码/解码、数据缓存。

### 3.6.4 MAC 地址与 MAC 帧格式（重点）

**MAC 地址**：
- **48 位（6 字节）全球唯一**，固化在网卡 ROM 中，用 12 个十六进制数表示；
- 高 24 位 = 厂商代码，低 24 位 = 厂商分配的序列号；MAC 地址**不会改变**；
- 路由器接入多个网络需配备多个适配器，**每个接口有独立 MAC 地址**；
- 适配器收到每个 MAC 帧都用硬件检查目的地址，分三类：**单播帧**（一对一）、**广播帧**（目的地址全 1，对全体）、**多播帧**。

**MAC 帧格式（IEEE 802.3）**：

| 目的地址 | 源地址 | 类型 | 数据（IP 数据报） | FCS |
| ---- | ---- | ---- | ---- | ---- |
| 6B | 6B | 2B | 46 ~ 1500B | 4B |

- 帧前面有**前导码**（同步时钟，不算帧的一部分）；
- **类型字段**：标识上层使用的协议（如 IP）；
- **FCS**：帧检验序列，用 CRC 校验；
- **数据字段长度 46~1500B**：46B 下限保证满足最短帧长 64B（6+6+2+46+4=64）；1500B 上限即 MTU。

**无效 MAC 帧**（任一即丢弃）：
1. 帧长度不是正数个字节；
2. FCS 检出差错；
3. 数据字段长度不在 46~1500B 之间。

**转发与 MAC 地址**：
- 集线器**无 MAC 地址**，无脑转发（广播）；交换机、路由器有 MAC 地址，可查表定向转发；
- 广播帧在局域网内被所有站接收，但**路由器不会转发广播帧**到其他网络。

### 3.6.5 IEEE 802.11 无线局域网

- MAC 层使用 **CSMA/CA** 协议；
- 两种组网：**有固定基础设施**（WiFi，通过 AP 接入点）；**无固定基础设施**（移动自组织网络，如隔空投送）；
- 家用路由器 ≈ **路由器 + 以太网交换机 + AP**；
- 不同协议网络通过**门户 Portal 网桥**互连；
- 同一 802.11 局域网内两个移动站**不能直接通信**，必须通过 **AP 转发**。

**帧分类**：
- **数据帧**；
- **控制帧**：ACK、RTS、CTS；
- **管理帧**：探测请求、探测响应等。

**802.11 帧的地址字段**（三个地址，取决于帧去向）：

| 阶段 | 地址1（接收） | 地址2（发送） | 地址3（目的/源） |
| ---- | ---- | ---- | ---- |
| 去往 AP | AP 地址 | 源站 A 地址 | 最终目的 B 地址 |
| 来自 AP | 最终目的 B 地址 | AP 地址 | 源站 A 地址 |

### 3.6.6 高速以太网

- **100Mbps**：快速以太网；
- **1Gbps**：吉比特以太网；
- **10Gbps**：光纤，全双工（点对点），不再需要 CSMA/CD；
- 半双工时仍用 CSMA/CD。

## 3.7 广域网

**特点**：覆盖很大的物理范围，连接不同协议的异构网络，使用**分组交换**技术。

### 3.7.1 PPP 协议（点对点协议，重点）

**应用**：拨号上网等点对点链路；只支持**全双工**。

**主要特点**：
1. **简单**：对帧**不纠错、不编号、不进行流量控制**，把复杂工作交给上层协议（TCP）处理；
2. **封装成帧**：通过**帧定界符**标识帧的边界；
3. **透明传输**：异步线路用**字节填充**，同步线路用**零比特填充**；
4. **支持多种网络层协议**：不限定上层协议，通过协议字段区分（IPv4 / IPv6 等）；
5. **多种类型链路**：串行/并行、同步/异步、电/光均可运行；
6. **差错检测**：只检错不纠错，检测到错误帧直接**丢弃**，不重传；
7. **检测连接状态**：通过**链路控制协议（LCP）** 定期探测链路是否正常；
8. **MTU**：数据部分最大长度默认 **1500 字节**，超过需分片；
9. **网络层地址协商**：由**网络控制协议（NCP）** 完成双方 IP 地址等参数的协商。

### 3.7.2 HDLC 协议（高级数据链路控制）

- 面向比特的同步链路控制协议，使用**零比特填充**保证透明传输；
- 原笔记内容较简略，属于了解型考点：帧结构、三种帧类型（信息帧 I、监督帧 S、无编号帧 U）为常见延伸考点。

## 3.8 数据链路层设备

### 3.8.1 冲突域与广播域（基础概念）

- **冲突域**：同一时刻只能有一个结点发送数据的范围（集线器所有端口在一个冲突域）；
- **广播域**：广播帧能到达的范围；
- **集线器**：不隔离冲突域也不隔离广播域；
- **交换机（二层）**：**隔离冲突域**，不隔离广播域；
- **路由器（三层）**：既隔离冲突域也隔离广播域。

### 3.8.2 网桥

- 连接两个（或多个）局域网的**数据链路层设备**；
- 能识别 MAC 地址并**有选择地转发**帧，从而隔离冲突域、减少无效流量。

### 3.8.3 以太网交换机（重点）

**本质**：**多端口网桥**，工作在数据链路层，**全双工**。

**特点**：
- 根据 **MAC 地址**转发帧（查交换表）；
- 每个端口是一个独立冲突域 → **隔离冲突域**；
- 有并行性：多个端口可同时通信；
- 全双工工作；
- 不能互连采用不同网络层协议的异构网络（这是路由器的活）。

**自学习功能（即插即用，重点）**：
- 维护**交换表**：MAC 地址 ↔ 端口号的对照表（同一局域网内 MAC 高 24 位相同，实际只需记录后 24 位）;
- 转发流程：
  1. 收到帧，查表找**目的 MAC** 对应端口；
  2. 表中有 → 从对应端口转发（若目的端口=源端口则丢弃）；
  3. 表中没有 → **向除源端口外所有端口广播（泛洪）**；
  4. 每收到一帧，把**源 MAC + 入端口**记入交换表（更新/新增）；
  5. 表项有**有效期（TTL）**，超时自动作废，防止设备移动后表项失效。

**交换方式对比**：

| 方式 | 做法 | 优点 | 缺点 |
| ---- | ---- | ---- | ---- |
| **直通转发** | 只检查前 6 字节（目的 MAC）就立即转发 | **时延低**（类似电路交换） | 不检错，坏帧也转发 |
| **存储转发** | 完整接收整帧并做差错检测后再转发 | 支持**速度匹配**、协议转换、差错检测 | **转发时延高** |

### 3.8.4 虚拟局域网 VLAN

**产生原因**：交换机互联的多个交换机处于**同一个广播域**，广播帧泛滥会引发：
1. **广播风暴**（占用带宽）；
2. 难以管理；
3. 安全隐患（广播可被所有站接收）。

**VLAN 作用**：把一个物理局域网在**逻辑上划分为多个局域网**，每个 VLAN 是一个独立的广播域，广播只在 VLAN 内传播。

**分割广播域的方式**：
1. **路由器**（网络层设备）：成本高；
2. **虚拟局域网 VLAN**：成本低、灵活。

**VLAN 划分方式**：
1. **基于端口**：把若干物理接口划分到同一逻辑组（最常用）；
2. **基于 MAC 地址**；
3. **基于 IP（网络层协议）**。

**802.1Q 帧（VLAN 标记）**：在标准以太网帧中插入 4 字节 VLAN 标记（含 VLAN ID），帧结构变为：
`前导码 + 6B 目的 + 6B 源 + 4B VLAN 标记 + 2B 类型 + 46~1500B 数据 + 4B FCS`（总长 1518B → 1522B）。

## 3.9 全双工与半双工（易错考点）

| 设备 | 能否全双工 | 原因 |
| ---- | ---- | ---- |
| **集线器** | ❌ 不能 | 共享信道（总线），只能半双工 |
| **交换机** | ✅ 能 | 端口独立，点到点连接 |
| **路由器** | ✅ 能 | 端口独立，点到点连接 |

- **只有集线器是半双工的**，交换机和路由器都支持全双工；
- **CSMA/CD 是半双工机制**：全双工链路是点到点连接，收发通道完全分开（双绞线一对发送、一对接收），不会碰撞，因此**全双工以太网不使用 CSMA/CD**；
- 光纤全双工通常通过双纤或单纤 WDM/BiDi 实现；单芯光纤无复用技术则只能半双工。
