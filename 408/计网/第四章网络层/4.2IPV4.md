## IP数据报分片

> 当 IP 数据报长度超过链路层 **MTU** 时，路由器将其拆分为多个较小的分片，各分片独立转发，到达目的主机后由 IP 层重新组装。 大于 1500B就需要分片

### 分片涉及的三个首部字段

| 字段           | 含义                                | 规则                           |
| ------------ | --------------------------------- | ---------------------------- |
| **标识**（16位）  | 同一原始数据报的所有分片标识相同                  | 目的主机据此将分片归组                  |
| **标志**（3位）   | DF：1=禁止分片，0=允许；MF：1=后面还有分片，0=最后一个 | DF=1 且超出 MTU 则丢弃并回送 ICMP     |
| **片偏移**（13位） | 该分片数据部分在原始数据报中的起始位置               | 以 **8 字节**为单位，实际偏移 = 片偏移 × 8 |
```
MTU = 800,L = 1580B 的IP，首部为20B

20 + 1560B
20 + 780B
MTU不一定要全用上，必须是8的整数倍
780 / 8 = 97......4 = 776
所以一个分片是776个数据


```

### 分片规则

- 每个分片的**数据部分必须是 8B 的整数倍**（片偏移以此为前提）
- 分片后各分片都是独立 IP 数据报，可走不同路径，到达顺序不保证
- **分片只在路由器进行，重组只在目的主机进行**——中间路由器不负责重组
- DF=1 的数据报遇到 MTU 不够时，路由器直接丢弃并回复 **ICMP 终点不可达**（需分片但 DF 置位）

### 分片计算示例

将总长度 3820B（首部 20B + 数据 3800B）的数据报通过 MTU=1420B 的链路：

- 每片可携带数据：1420 − 20 = **1400B**，且须为 8 的倍数
- 计算：3800 ÷ 1400 = 2 余 1000 → 共 **3 片**

| 分片 | 数据长度 | 片偏移 | MF |
|------|----------|--------|-----|
| 第 1 片 | 1400B | 0 | 1 |
| 第 2 片 | 1400B | 175（1400/8） | 1 |
| 第 3 片 | 1000B | 350（2800/8） | 0 |

# ARP地址解析
查询同一网络的<IP地址，MAC地址>
**数据结构**：
ARP表
局域网内每一项的IP和MAC映射关系
每个主机和路由器都有自己的ARP表
48位
## 过程

> ARP 解析分为两步：**广播请求 + 单播响应**，通过"问-答"机制完成 IP 到 MAC 的映射。
> 
> 会直接封装到数据帧中，不会使用IP 协议，不加入IP首部
1. **ARP 请求（广播）**
   - 发起方封装 ARP 请求分组，声明"我的 IP 是 X，MAC 是 Y，我想找 IP 为 Z 的主机"
   - 封装进 MAC 帧，目的 MAC 为**全 1 广播地址** `FF:FF:FF:FF:FF:FF`，源 MAC 为发起方 MAC
   - 以广播方 式发送到局域网内所有设备
1. **ARP 响应（单播）**
   - 目标设备收到请求后，确认自己持有 IP 地址 Z，回复"我就是，我的 MAC 是 V"
   - 封装进 MAC 帧，目的 MAC 为**发起方 MAC**，源 MAC 为目标设备 MAC
   - 以单播方式直接回复发起方
1. 双方各自将 `<IP, MAC>` 映射**存入 ARP 表**，后续通信直接查表，无需重复解析

## 四种情况
![](./picture/image-20260808151413.png)
> ARP 解析根据**发送方角色**（主机/路由器）和**目的主机所在网络**（同一网络/不同网络）两两组合，共四种典型场景。

- **情况① 主机 → 本网络另一主机**：发送方主机（如 H₁）在所在网络上**广播 ARP 请求**，直接找到目的主机（如 H₂）的 MAC 地址，后续直接用该 MAC 封装帧发送
- **情况② 主机 → 其他网络的主机**：发送方主机（如 H₁）在本网络上广播 ARP 请求，找到**默认网关路由器**（如 R₁）的 MAC 地址，将 IP 分组交给 R₁，剩余工作由路由器完成
- **情况③ 路由器 → 同一网络的主机**：路由器（如 R₁）在目的主机所在网络上广播 ARP 请求，直接找到目的主机（如 H₃）的 MAC 地址，然后转发
- **情况④ 路由器 → 不同网络的主机**：路由器（如 R₁）在当前网络上广播 ARP 请求，找到**下一跳路由器**（如 R₂）的 MAC 地址，将分组转发给 R₂，后续由 R₂ 继续处理

# 网际报文控制协议ICMP（网络层）
需要封装到IP数据报内
IP协议为ICMP服务
**作用**：让及主机或路由器互相报告网络中发生的差错和异常控制

对于已经分片的分组，只对第一个分片产生ICMP差错报文
对于多播分组，不发送ICMP


> ICMP 报文分为**差错报告报文**和**询问报文**两大类：前者用于向源主机报告网络传输中的各类异常，后者用于网络诊断和连通性测试。
 
### 差错报告报文（5种）

- **终点不可达**（类型3）
  - 路由器发现**目的 IP 地址不可到达**时，向源主机报告（路由不可达）
  - 目的主机发现**目的端口号不存在**（无对应进程）时，向源主机报告（端口不可达）
- **时间超过**（类型11）
  - 路由器收到 **TTL=0** 的 IP 数据报时将其丢弃，并向源主机报告（路程太远，跳数耗尽）
  - 目的主机在**规定时间内未收齐所有分片**时，将已收到的分片全部丢弃并报告
- **参数问题**（类型12）—— 当 IP 数据报**首部参数不合法**或**首部校验出错**时，路由器或主机向源主机报告
- **改变路由/重定向**（类型5）—— 路由器告诉源主机："对于该目的网络，请改用另一台路由器转发，路径更短"
- **源点抑制**（类型4，2012 年已废弃）—— 用于通知源主机网络发生拥塞，请求降低发送速率

### 询问报文（2 对，成对出现）

- **回送请求与回答**（Echo Request/Reply，类型 8/0）
  - A 向 B 发送 **Echo Request**："在吗？请回答我！"
  - B 收到后回复 **Echo Reply**："在！"
  - 典型应用：**ping 命令**，用于测试网络连通性
- **时间戳请求与回答**（Timestamp Request/Reply，类型 13/14）
  - A 向 B 发送 **Timestamp Request**，告知自己当前的发送时间
  - B 回复 **Timestamp Reply**，告知收到请求的时间和发出回答的时间
  - 用于估算往返时延（RTT）和时钟同步

**不发送ICMP报文**
1. 对ICMP差错报文
2. 对抵押给分片的数据报片的所有后续数据报片
3. 对多播地址的数据报
4. 有特殊地址（127.0.0.1，0.0.0.0）
5. 组播
# IP数据报分组转发的过程

> 路由器收到 IP 数据报后，按**特定主机路由 → 网络路由 → 默认路由**的优先级逐级查找转发表，找到匹配项后从对应接口转发出去；若全部不匹配则丢弃并回送 ICMP 终点不可达。

## 路由表结构与匹配优先级

转发表中每条表项为 `<目的网络地址, 子网掩码, 下一跳地址, 转发接口>`，查找时按以下优先级：

1. **特定主机路由**：为某台特定主机单独设置的路由，子网掩码为 `255.255.255.255`，优先级最高
2. **网络路由**：匹配目的主机所在的网络前缀，采用**最长前缀匹配**——同一目的地址可能命中多条网络路由，选子网掩码最长（即地址块最小、最具体）的那条
3. **默认路由**：`0.0.0.0/0`，匹配所有目的地址，优先级最低；当目的网络不在路由表中时走默认路由（通常指向 ISP 边界路由器）

## 路由器分组转发算法

1. **提取目的 IP**：从 IP 数据报首部取出目的 IP 地址 D
2. **查特定主机路由**：用 D 与所有特定主机路由逐条匹配，命中则直接转发
3. **查网络路由**：将 D 与每条网络路由的子网掩码做按位与，结果与对应目的网络地址比较；使用最长前缀匹配选择掩码最长的那条
4. **查默认路由**：若网络路由也无匹配，走默认路由 `0.0.0.0/0`
5. **全部未命中**：丢弃数据报，向源主机发送 **ICMP 终点不可达**（类型 3）

## 分组转发 vs 路由选择

|          | 分组转发         | 路由选择             |
| -------- | ---------------- | -------------------- |
| 作用层面 | **数据平面**     | **控制平面**         |
| 功能     | 查转发表、转发包 | 构建和维护路由表     |
| 时间粒度 | 每个分组到达时   | 周期性或拓扑变化触发 |
| 关注点   | 快——哪个接口出去 | 准——哪条路径最优     |

- **转发表由路由表导出**：路由协议算出最优路径写入路由表，再精简为转发表供硬件高速查找
- 路由器查转发表时采用最长前缀匹配，常用**二叉线索树（Trie）**等数据结构加速
