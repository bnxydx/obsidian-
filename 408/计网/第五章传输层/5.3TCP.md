# TCP报文段

## 一次TCP连接可以传输多少报文
需要先协商一个最大段长MSS = 1000B
每个数据报只要不超过最大段长就可以
- 每次建立TCP连接，可以传输多个报文，并且是双向的
- TCP是面向字节流的，把应用层给的所有报文全拆分然后传输
- UDP是面向报文的，

## TCP段格式
![](Pasted%20image%2020260803094034.png)

 - TCP首部 20B~60B
1. 源端口：16bit
2. 目的端口：16bit
3. 序号seq：标记数据部分第一个字节在原始字节流的位置
	1. 可能不从0开始
	2. 作用：拆分和重组
4. 确认号ack：期待收到下一个报文段的下一个序号，用于反馈，表示在这个确认号之前的所有字节都已经正确收到（累计确认）
5. ACK：
	1. == 0 则ack无效
	2. == 1 则ack有效
	3. 只有第一个握手的ACK = 0，其他都是1
6. 数据偏移：表示TCP首部的长度（4字节的单位） 4bit
	1. 所以TCP首部都是4B的整数倍
7. 保留 6bit
8. URG紧急位1bit
	1. == 1 表示是紧急数据，需要插队发送
		1. 同时表示**紧急指针**是有效的
	2. == 0表示是不紧急
9. 紧急指针：16bit
	1.  紧急数据的专用序号
10. PSH推送位1bit
	1. == 1表示希望接收方快速回复
11. PST复位位 1bit
	1. == 1表示发送方出现严重错误，需要释放并重新建立连接，也可以拒绝一个非法报文段（黑客）
12. SYN 同步位1bit
	1. == 1表示这是一个连接请求或连接接受报文
	2. 只有握手1和握手2 syn == 1，其他都是0
13. FIN终止位1bit
	1. 表示报文段的发送方数据已经发送完毕，要求释放连接
	2. 挥手1和挥手3的FIN=1，其他都是0  
14. 窗口rwnd   16bit
	1. 表示接收窗口的大小
	2. 表示还能接收多少数据，（实现流量控制）
15. 校验和16bit
	1. 和UDP相同
	2. 先加12bit伪首部（源IP+目的IP+0+6+TCP长度）
16. 选项（长度可变）
	1. MSS，在握手1和握手2协商的 
17. 填充


## TCP的三大阶段
1. 建立连接（三次握手）
2. 数据传输
3. 释放连接（四次挥手）

### 三次握手（建立连接）

| 步骤  | 方向      | 标志位          | 序列号/确认号          | 客户端状态                  | 服务器状态                  |
| --- | ------- | ------------ | ---------------- | ---------------------- | ---------------------- |
| ①   | 客户端→服务器 | SYN=1        | seq=x            | SYN-SENT               | LISTEN → SYN-RCVD      |
| ②   | 服务器→客户端 | SYN=1, ACK=1 | seq=y, ack=x+1   | SYN-SENT → ESTABLISHED | SYN-RCVD               |
| ③   | 客户端→服务器 | ACK=1        | seq=x+1, ack=y+1 | ESTABLISHED            | SYN-RCVD → ESTABLISHED |

握手完成后双方进入 **ESTABLISHED** 状态，开始全双工数据传输。

### 四次挥手（释放连接）

| 步骤                  | 方向      | 标志位          | 序列号/确认号          | 客户端状态                    | 服务器状态                    |
| ------------------- | ------- | ------------ | ---------------- | ------------------------ | ------------------------ |
| ①                   | 客户端→服务器 | FIN=1        | seq=u            | ESTABLISHED → FIN-WAIT-1 | ESTABLISHED              |
| ②                   | 服务器→客户端 | ACK=1        | ack=u+1          | FIN-WAIT-1 → FIN-WAIT-2  | ESTABLISHED → CLOSE-WAIT |
| 客户端到服务器端的线路断开变成单工通信 |         |              |                  |                          |                          |
| ③                   | 服务器→客户端 | FIN=1, ACK=1 | seq=v, ack=u+1   | FIN-WAIT-2               | CLOSE-WAIT → LAST-ACK    |
| ④                   | 客户端→服务器 | ACK=1        | seq=u+1, ack=v+1 | FIN-WAIT-2 → TIME-WAIT   | LAST-ACK → CLOSED        |

# TCP可靠传输
以字节位单位的滑动窗口来实现可靠传输

1. 发送方收到一个报文
	1. rwnd = 20 ,ack = 31，表示接收方的窗口大小为20，希望收到下一个的序号是31
2. 发送方设置发送窗口 = 20
3. 把窗口内的数据一次发送，并且暂时保留，直到收到确认
4. 接收方可以使用累计确认的方法，把之前收到的返回一个ack就可以

### 发送窗口
- 发送方在未收到确认的情况下，最多能连续发送的数据量。
- 发送窗口大小 = **min(rwnd, cwnd)**，即接收方通告窗口和拥塞窗口的较小值。
- 发送窗口内的数据分三类：已发送未确认、允许发送但尚未发送、暂时不允许发送（窗口外）。
- 发送方必须为窗口内已发送的报文保留副本，直到收到确认才能释放。

### 接收窗口
- 接收窗口大小 = **rwnd**，即接收方当前还能接收的字节数。
- 接收方只接收落在接收窗口内的数据，窗口外的数据直接丢弃。
- 接收窗口大小 = 接收缓冲区总大小 - 已接收但尚未被应用层取走的数据量。

### 窗口滑动
- **前滑动（窗口前移）**：收到新的确认号后，发送窗口后沿向前移动，前沿也相应前移，允许发送新数据。
- **前沿收缩**：TCP 标准不赞成前沿向后收缩（缩小窗口），但允许前沿不动。
- **后沿不动**：有部分数据未被确认时，后沿无法前移，窗口不滑动，发送被阻塞。

### 累计确认
- 确认号 ack = N，表示序号 N-1 及之前的所有字节均已正确收到，期望收到序号为 N 的字节。
- 优点：即使前面的 ACK 丢失，后续的 ACK 也能覆盖前面的确认信息，降低了 ACK 丢失的影响。
- 缺点：发送方无法精确知道哪些中间报文已到达，只能知道连续到达的最长前缀。

### 捎带确认
- 接收方在向发送方回传数据时，将 ACK 附带在数据报文中发送，减少单独 ACK 报文的数量。
- 若暂时没有数据要发，ACK 也会单独发送（不会无限等待）。
- 通常会延迟一小段时间（如 200ms），看是否有数据要回传，若有则捎带，若无则单独发 ACK。

### 重传
#### 超时重传
如果在重传时间没有收到确认就重传

#### 冗余ack
TCP规定，如果发送方收到对同一个报文的3个**冗余确认**，就认为被确认报文段之后的报文段已经丢失
其实是相当于收到四个ack，后三个是冗余ack

## 流量控制
发送方不要发太快，需要让他接收
接收方有一额接收窗口rwnd
- **第一次握手（SYN）**：客户端告诉服务端“我的**初始接收窗口**是多大”。
- **第二次握手（SYN + ACK）**：服务端告诉客户端“我的**初始接收窗口**是多大”。
- **第三次握手（ACK）**：客户端再次确认，并再次附带当前的接收窗口大小。
### rwnd 与滑动窗口
- 接收方通过 TCP 首部的**窗口字段（rwnd，16bit）**通告自身剩余接收缓冲区大小。
- 发送方据此调整发送窗口，确保不淹没接收方。
- rwnd 是动态变化的：应用层取走数据 → rwnd 增大；接收方收到数据 → rwnd 减小。

### 零窗口与持续计时器
- **零窗口**：当 rwnd = 0 时，发送方必须停止发送数据（紧急数据除外）。
- **零窗口死锁风险**：接收方后来窗口恢复并发送了窗口更新报文，但该报文若丢失，双方将互相等待，形成死锁。
- **持续计时器（Persistence Timer）**：
  - 发送方收到零窗口通告后启动持续计时器。
  - 计时器超时后，发送方发送一个**零窗口探测报文**（仅 1 字节），询问接收方窗口是否已恢复。
  - 若窗口仍为 0，重新启动计时器；若窗口恢复，发送方继续正常发送。

### 流量控制 vs 拥塞控制

| 对比维度 | 流量控制          | 拥塞控制         |
| ---- | ------------- | ------------ |
| 针对问题 | 接收方处理能力不足     | 网络链路拥塞       |
| 控制变量 | rwnd（接收方通告）   | cwnd（发送方维护）  |
| 作用范围 | 点到点（端到端）      | 全局（涉及网络所有主机） |
| 实现位置 | 接收方 → 发送方（反馈） | 发送方自行判断      |

## 拥塞控制
拥塞控制的目标是：使网络能够承载当前负载，是一个全局性的过程，
为了防止过多数据注入网络，保证路由器或链路不过载

拥塞控制的核心假设：**超时 / 重复 ACK 均意味着网络拥塞**。

### 核心变量
发送方维持一个拥塞窗口，取决于网络的拥塞程度，并且动态变化，
发送窗口 = min（拥塞窗口，接收窗口）
MSS：作为拥塞窗口大小的单位

| 变量 | 含义 | 初始值 |
|------|------|--------|
| cwnd（拥塞窗口） | 发送方根据网络状况动态调整的窗口，单位 MSS | 1 MSS |
| ssthresh（慢开始门限） | 慢开始与拥塞避免的分界线 | 通常初始很大（如 64 KB） |
| rwnd（接收窗口） | 接收方通告窗口 | 由接收方决定 |
| 发送窗口 | min(cwnd, rwnd) | — |

### 算法一：慢开始（Slow Start）
- **阶段**：TCP 连接建立后，或超时重传后进入。
- **规则**： 
  - cwnd 从 1 MSS 开始。
  - 每收到一个对新报文的 ACK，cwnd += 1 MSS（即每经过一个 RTT，cwnd 翻倍）。
  - 当 cwnd ≥ ssthresh 时，停止慢开始，进入**拥塞避免算法**。（不断增加，一直到一个值的时候使用拥塞避免算法）
- **特点**：cwnd 呈指数增长，快速探测网络带宽上限。

### 算法二：拥塞避免（Congestion Avoidance）
- **触发**：cwnd ≥ ssthresh 后进入。
- **规则**：每经过一个 RTT，cwnd += 1 MSS（每个 ACK 增加 cwnd * (1/cwnd) ≈ 1/cwnd 个 MSS，等效线性增长）。
- **特点**：cwnd 呈线性缓慢增长，谨慎试探网络剩余容量。
- **超时处理**：发生超时 → ssthresh = cwnd（当前的窗口大小） / 2，cwnd = 1 MSS，回到**慢开始**
	- 当涨到24时，新的拥塞避免的阈值 = 12
	- 然后把窗口设置为1从1开始进行慢开始

### 算法三：快重传（Fast Retransmit）
- **触发**：发送方连续收到 3 个冗余 ACK。
- **规则**：不等超时计时器到期，立即重传丢失报文。
- **与超时重传的关键区别**：收到 3 个冗余 ACK 说明后续报文仍在到达（网络未完全瘫痪），不应像超时那样把 cwnd 打回 1。

### 算法四：快恢复（Fast Recovery）
- **触发**：快重传发生后（即收到 3 个冗余 ACK 并执行快重传后）。
- **规则**：
  1. ssthresh = cwnd / 2（记录当前拥塞窗口的一半作为新门限）。
  2. cwnd = ssthresh（不是降到 1，因为 3 个冗余 ACK 意味着已有 3 个报文离队，网络仍有传输能力）。
  3. 此后每收到一个重复 ACK，cwnd += 1 MSS（允许继续发新数据）。
  4. 收到新数据的 ACK 后，cwnd = ssthresh（收缩到门限值），然后进入**拥塞避免**阶段。
- **强相关**：快恢复通常与快重传配对使用（即 TCP Reno 版本），避免了超时后 cwnd 暴跌到 1 的剧烈震荡。

### 完整状态变迁图（TCP Reno）

```
连接建立 → [慢开始] ── cwnd ≥ ssthresh ──→ [拥塞避免]   超时
                ↑                               │
                │ 超时                          │ 超时
                │ ssthresh=cwnd/2               │ ssthresh=cwnd/2
                │ cwnd=1                        │ cwnd=1
                └────────────────────────────────┘
                
[拥塞避免] ── 3个冗余ACK ──→ [快重传 + 快恢复]        收到3个ack 
                ↑                    │
                │                    │ ssthresh=cwnd/2
                │                    │ cwnd=ssthresh
                │                    │ 收到新ACK后 cwnd=ssthresh
                └────────────────────┘  → 进入拥塞避免
```

- 超时 → 慢开始（剧烈反应，网络可能严重拥塞）
- 3 个冗余 ACK → 快重传 + 快恢复（温和反应，网络仍有传输能力）
- 快恢复后直接进入拥塞避免，跳过慢开始的指数增长阶段。
