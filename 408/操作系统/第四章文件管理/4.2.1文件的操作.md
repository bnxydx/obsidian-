 操作系统提供一系列的**系统调用**对文件的创建，删除，读写，开关等操作
# 创建文件
涉及元数据分配，存储空间预留，目录注册

1. 检查文件名是否合法，重名
2. 分配索引节点inode，初始化数据
	1. 类型
	2. 大小
	3. 权限
	4. 时间戳
	5. 物理块指针：磁盘块6 1 4
	6. 占用
3. 分配磁盘块
4. 在目录中新建目录项
5. 更新文件系统元数据
6. 打开并返回文件描述符
# 删除文件
 撤销目录可见性，回收元数据，释放存储空间
1. 路径解析与定位，获取inode或FCB，并验证权限
2. 检查使用状态和硬链接计数
	1. 文件被打开则无法删除
	2. 若计数 > 1则仅删除当前**目录项(文件磁盘索引节点)** 并计数减1，不回收inode和磁盘块
	3. 若 == 1则完整删除
3. 溢出目录的目录项
4. 释放索引节点
5. 释放磁盘块
6. 释放内存临时资源
7. 更新文件系统元数据

# 读文件&写指针
依据当前读（写）指针位置，从指定块读取数据，并且更新指针

# 文件打开open
操作系统的文件打开：
当文件被首次打开，需要通过系统调用`open`将其打开，把FCB读到内存

`open`
1. 根据文件路径定位到目录项
2. 将关键信息(目录项)载入内存
3. 在打开文件表中创建一个表目

`read`
是把文件内容读到内存
### 读文件
1. 按照文件描述符打开文件表找到目录项
2. 按照存取控制说明检查合法性
3. 按照目录项中文件的逻辑和物理组织形式，将逻辑记录号转为物理记录号
4. 向设备驱动器发IO请求
## 打开文件表
多个进程打开同一个文件，会指向系统打开文件表的同一项，并指向同一个FCB
会避免重复操作
一个进程可能打开多个文件

![](Pasted%20image%2020260619142912.png)
进程的打开文件表中数据下表是文件描述符
不同的进程打开文件表打开同一个文件的描述符可能是不同的，但是系统打开文件表是一定相同的
**系统打开文件表**
全局
1. 磁盘位置
2. 文件大小
3. 访问时间
每一项都有一个**打开计数器**，记录有多少进程打开了该文件，

**进程打开文件表**
每个进程独有
1. 当前读写指针
2. 访问权限
3. 文件打开模式

>一旦成功执行open（）系统调用，后续所有文件操作【包括read、write、lseek、close等]均不再使用文件名，而是通过文件描述符进行，这一机制是文件管理的核心考点。
### 文件打开的完整过程（流程总结）

1. **逐级遍历目录**：根据文件路径逐级遍历，将所需目录文件从磁盘加载至内存，定位目标文件的目录项
2. **提取索引节点编号**：从目录项中获取 inode 编号
3. **查询系统打开文件表**：以 inode 编号为关键字，在系统打开文件表中查找
   - **未找到**：从磁盘读取索引节点到内核缓冲区 → 在系统表中创建新项 → 打开计数初始化为 1
   - **已存在**：仅将该项的打开计数 +1
4. **分配进程表项**：在发起请求的进程的进程打开文件表中分配新表项，指向系统表项索引
5. **返回文件描述符**：将该进程表项的索引号作为 fd 返回给用户进程，后续 read/write 等均通过 fd 操作

# 文件的关闭
1. 调用close
2. 从进程打开文件表删除对应项
3. 将系统打开文件表中的对应项的打开计数器减1
4. 一旦== 0说明无任何进程引用可以安全的删除在系统表中的项

# 进程打开文件表 vs 系统打开文件表

## 进程打开文件表（每个进程独有）

| 内容 | 说明 |
|------|------|
| 文件描述符（fd） | 表项的索引号，返回给用户进程，后续 read/write/close 均通过 fd 操作 |
| 当前读写指针 | 记录该进程对该文件的读写当前位置 |
| 访问权限 | 如只读、只写、读写等 |
| 文件打开模式 | 如覆盖、追加等 |
| 指向系统表项的索引 | 指向系统打开文件表中的对应项 |

> 不同进程打开同一个文件时，各自的进程打开文件表中的 fd 可能不同，但指向系统打开文件表的同一项。

## 系统打开文件表（全局唯一）

| 内容 | 说明 |
|------|------|
| 磁盘位置 | 文件在磁盘上的物理位置信息 |
| 文件大小 | 当前文件大小 |
| 访问时间 | 最近访问时间等时间戳 |
| 打开计数器 | 记录当前有多少进程打开了该文件；每 open 一次 +1，每 close 一次 -1；减到 0 时可以从系统表中删除该项 |
| 指向 FCB/索引节点 | 指向内存中的 FCB 或索引节点，避免重复加载 |
