 # 5.3 外存管理 —— 磁盘与SSD

## 一、磁盘结构

### 1.1 基本组成

| 概念                      | 说明                                                            |
| ----------------------- | ------------------------------------------------------------- |
| **盘面（Platter Surface）** | 磁盘由多个盘片组成，每个盘片有上下两个盘面，每个盘面对应一个磁头                              |
| **磁道（Track）**           | 盘面上的一圈**同心圆环**，数据沿磁道存放                                        |
| **扇区（Sector）**          | 每个**磁道**被划分为**若干弧段**，是磁盘读写的最小单位（通常 512B 或 4KB），**盘面会有上下两个盘面** |
| **柱面（Cylinder）**        | 所有盘面中同一半径位置的磁道集合。柱面号 = 磁道号                                    |
| **磁盘驱动器**               | 包括磁头臂、磁头、主轴等机械部件                                              |
|                         |                                                               |

### 1.2 磁盘地址

磁盘物理地址由三元组定位：

$$
\text{磁盘地址} = (\text{柱面号},\ \text{磁头号},\ \text{扇区号})
$$

- **柱面号（Cylinder #）**：定位到哪个磁道（所有盘面的同一半径磁道）
- **磁头号（Head #）**：定位到哪个盘面（即哪个磁头）
- **扇区号（Sector #）**：定位到磁道上的哪个扇区

> 读/写数据时，先移动磁头臂到指定柱面（寻道），再选择磁头（切换盘面无需机械移动），最后等待扇区旋转到磁头下方。

## 二、磁盘读写时间

一次磁盘读写操作的总时间为三部分之和：

$$
T = T_s + T_r + T_t
$$

### 2.1 寻道时间（Seek Time）$T_s$
磁头在不同的磁道移动的时间

- 磁头臂移动到指定柱面（磁道）所需的时间
- **占比最大**，是影响磁盘读写性能的主要因素
- 包括启动磁头臂的时间 $s$（常数）和跨越磁道的时间：$T_s = s + m \times n$
  - $m$：跨越一条磁道的时间（常数，与磁盘转速相关）
  - $n$：跨越的磁道数

### 2.2 旋转延迟（Rotational Latency）$T_r$

- 找到目标扇区
- 平均旋转延迟 = **旋转一圈时间的一半**
- 例：7200 RPM → 一圈约 8.3ms → 平均旋转延迟约 4.15ms

### 2.3 传输时间（Transfer Time）$T_t$

- 从扇区读取数据
  - $b$：要读/写的字节数
  - $r$：磁盘每秒转数
  - $N$：一个磁道上的字节数

> **性能瓶颈**：寻道时间 >> 旋转延迟 >> 传输时间。因此磁盘调度算法的核心目标是**减少寻道时间**。

## 三、磁盘调度算法（核心重点）

> 目标：合理安排多个磁盘 I/O 请求的处理顺序，最小化总寻道时间。

### 3.1 先来先服务 FCFS（First Come First Served）

- **思想**：按请求到达的先后顺序依次处理
- **特点**：
  - 公平、实现简单
  - 寻道路径可能反复横跳，性能较差
  - 适用于请求较少、I/O 负载低的场景
- **示例**：磁头在 50，请求序列 [98, 183, 37, 122, 14, 124, 65, 67]
  - 寻道路径：50→98→183→37→122→14→124→65→67，总寻道距离极大
![](Pasted%20image%2020260620155426.png)
![](Pasted%20image%2020260620155441.png)
### 3.2 最短寻道时间优先 SSTF（Shortest Seek Time First）

- **思想**：每次选择与当前磁头位置距离最近的请求先处理（贪心思想）
- **特点**：
  - 相比 FCFS 显著减少平均寻道时间
  - 吞吐量优于 FCFS
  - **缺点——饥饿（Starvation）**：磁头附近持续有新请求时，远端请求可能长期得不到服务
- **与 SJF 调度类比**：都是最短优先，都面临饥饿问题
![](Pasted%20image%2020260620155539.png)
### 3.3 扫描算法 SCAN（电梯算法）

- **思想**：磁头沿一个方向移动，处理该方向上所有请求，到达该方向最远端后反向移动
  - 类似电梯运行逻辑，故称"电梯算法"
- **特点**：
  - 克服了 SSTF 的饥饿问题
  - 寻道性能较好
  - **缺点**：对两端磁道的请求不公平，刚被扫过的区域新到的请求需等待磁头折返
- **变体**：通常假定初始方向为磁道号增大的方向
![](Pasted%20image%2020260620155714.png)
### 3.4 循环扫描算法 C-SCAN（Circular SCAN）

- **思想**：磁头只沿一个方向移动处理请求，到达最远端后**立即复位**到起始端（反向移动时不处理任何请求）
  - 将磁盘磁道视为一个循环队列
- **特点**：
  - **只处理一个方向的请求**
  - 各磁道响应时间更均匀，消除了 SCAN 对两端磁道的不公平
  - 平均寻道时间可能略大于 SCAN（因复位过程不处理请求）
  - 适合有规律、均匀分布的请求负载
  - 其实只要移动dap
![](Pasted%20image%2020260620155804.png)
### 3.5 LOOK 算法

- **思想**：SCAN 的改进版——磁头移到**该方向上最远的请求**处即折返，无需到达磁盘物理最边缘
- **特点**：减少了无请求区域的空跑寻道，效率优于 SCAN

### 3.6 C-LOOK 算法

- **思想**：C-SCAN 的改进版——磁头移到该方向上最远的请求处后，立即复位到反方向最近的请求处
- **特点**：省去 C-SCAN 中到物理端点的空跑，效率优于 C-SCAN

### 3.7 算法对比总结

| 算法 | 寻道优化 | 是否饥饿 | 公平性 | 适用场景 |
|------|---------|---------|--------|---------|
| **FCFS** | 无 | 无 | 绝对公平 | 低负载、请求少 |
| **SSTF** | 强（贪心） | **有饥饿** | 差 | 通用，高吞吐 |
| **SCAN** | 较强 | 无 | 一般（两端不公平） | 负载均匀 |
| **C-SCAN** | 较强 | 无 | **较好**（各磁道均匀） | 响应时间要求均匀 |
| **LOOK** | 强 | 无 | 一般 | 通用，优于 SCAN |
| **C-LOOK** | 强 | 无 | 较好 | 通用，优于 C-SCAN |

> **记忆技巧**：LOOK 系列是 SCAN 系列的"务实版"——不去物理端点，只到最远请求处就折返/复位。

## 四、磁盘管理

### 4.1 磁盘格式化

#### （1）低级格式化（物理格式化）

- **将磁盘划分为扇区**，每个扇区包括：
  - **头部**：扇区编号、校验码等
  - **数据区**（通常 512B）
  - **尾部**：ECC 纠错码
- 出厂前完成，用户一般不需要做
- 划分柱面、磁道、扇区的物理结构
- 校验
#### （2）（分区）
把磁盘划分为若干逻辑区域

#### （3）逻辑格式化（高级格式化 ）

- 将磁盘分区后，在分区上建立文件系统数据结构：
  - **引导块（Boot Block）**
  - **超级块（Super Block）**：记录文件系统整体信息（类型、块大小、空闲块等）
  - **空闲空间管理结构**（位示图 / 空闲链表）
  - **i 节点区**（Unix/Linux）
  - **根目录**
- 逻辑格式化后，分区才能被操作系统正常挂载和使用

### 4.2 引导块（Boot Block ）（跳）

- 位于磁盘的固定位置（通常为第一个扇区，即 MBR 或 GPT 区域）
- 存储引导程序（Bootstrap Loader）
- 开机时 ROM 中的 BIOS/UEFI 固件读取引导块，加载操作系统内核

### 4.3 坏块处理（跳）

- **坏块**：由于磨损或制造缺陷而无法正常读写的扇区
- 处理方式：

| 方式 | 说明 |
|------|------|
| **硬件处理（扇区备用）** | 磁盘控制器预留备用扇区，发现坏块时自动重映射到备用扇区，对 OS 透明 |
| **OS 级处理** | 操作系统维护坏块列表，文件系统分配空间时避开坏块（如 FAT 表的坏簇标记） |

## 五、固态硬盘 SSD（跳Solid State Drive）

### 5.1 SSD vs HDD 对比

| 对比维度 | 机械硬盘 HDD | 固态硬盘 SSD |
|---------|-------------|-------------|
| **存储介质** | 磁介质盘片 | 闪存芯片（NAND Flash） |
| **读写方式** | 机械寻道 + 旋转 | 电子读写，无机械部件 |
| **随机访问** | 慢（需要寻道+旋转延迟） | 极快（接近内存） |
| **读写速度** | 受转速限制（5400/7200 RPM） | 远高于 HDD |
| **功耗** | 较高（电机驱动） | 低 |
| **抗震性** | 差（机械结构怕震动） | 强（无机械部件） |
| **噪音** | 有（盘片旋转+磁头移动） | 无 |
| **价格/容量比** | 低 | 高 |
| **寿命** | 理论上无限（磁介质） | **有限（闪存擦写次数有限）** |

### 5.2 SSD 关键问题

#### （1）写入前需擦除

- SSD 以**页（Page）**为单位读写，以**块（Block）**为单位擦除
- 写入新数据前，必须先擦除整个块（Erase-Before-Write）
- 这会导致**写放大（Write Amplification）**：实际写入的数据量 > 用户请求写入的数据量

#### （2）磨损均衡（Wear Leveling）

- **问题**：每个闪存块有擦写次数上限（通常几千到几万次），频繁擦写同一块会导致局部"磨穿"
- **策略**：
  - **动态磨损均衡**：将新写入的数据均匀分布到擦写次数少的块
  - **静态磨损均衡**：将不常修改的"冷数据"也搬到擦写次数多的块，释放出擦写次数少的块供频繁写入
- **目的**：延长 SSD 整体寿命，避免局部过早失效

#### （3）TRIM 命令

- 删除文件时，OS 通过 TRIM 命令告知 SSD 哪些页已不再使用
- SSD 可在后台预先擦除这些块，减少后续写入时的擦除等待
