# MSF-DETR 算法方案

## 一、算法名称

**MSF-DETR：Multi-Scale Fine-grained DETR**

中文名称：**多尺度细粒度 DETR 死禽小目标检测算法**

------------------------------------------------------------------------

## 二、研究目标

本课题面向密集笼养环境下的死禽自动检测问题，重点解决以下三个实际问题：

1.  **死禽目标尺寸较小、局部暴露**：目标只露出头部、身体局部或被笼架遮挡，容易漏检。
2.  **鸡群密集、目标相互遮挡**：多个鸡体重叠、笼网和背景干扰明显，容易出现漏检或定位不准。
3.  **死禽与休眠/趴卧活禽外观相似**：仅依靠常规检测特征容易产生误检。

考虑到当前自建数据集规模较小，本方案不把"堆叠大量复杂模块"作为主要路线，而采用**成熟检测框架 +
少量可验证改进 + 公开数据辅助预训练/验证**的方式，提高项目实际完成概率。

------------------------------------------------------------------------

# 三、总体技术路线

``` text
公开禽类数据集
        ↓
辅助预训练 / 数据扩充
        ↓
本课题死禽数据集
        ↓
RT-DETRv2 基线
        ↓
高分辨率特征增强
（探索 P2/P3 等浅层特征）
        ↓
多尺度注意力
        ↓
RT-DETRv2 检测头
        ↓
死禽检测结果
```

训练阶段额外加入：

``` text
检测特征
   ├────────→ 检测损失 L_det
   │
   └────────→ 特征投影层 → SupCon → L_supcon
```

最终训练目标：

\[ L = L\_{det} + `\lambda `{=tex}L\_{supcon} \]

其中：

-   (L\_{det})：RT-DETRv2 原有检测损失；
-   (L\_{supcon})：监督对比学习损失；
-   (`\lambda`{=tex})：SupCon 损失权重。

**SupCon 分支只在训练阶段使用，推理阶段删除，不增加部署时的检测分支。**

------------------------------------------------------------------------

# 四、为什么选择 RT-DETRv2

本项目不从零实现 DETR，而是基于成熟的 RT-DETR 系列实现进行修改。

主要考虑：

-   Transformer 检测框架与本课题的小目标、遮挡场景具有较好的研究契合度；
-   RT-DETR 系列本身面向实时目标检测，便于后续进行速度和部署实验；
-   使用已有实现可以显著降低从零实现 DETR 的风险；
-   可以把毕业设计的创新点集中在"高分辨率特征、多尺度注意力、细粒度特征学习"上，而不是重复实现基础检测器。

**注意：不能直接宣称 DETR 天生比 YOLO
更适合小目标。最终效果必须通过实验验证。**

------------------------------------------------------------------------

# 五、改进模块一：高分辨率特征增强

## 5.1 设计目的

死禽在监控画面中可能只占很小区域，经过多次下采样后，目标的边缘、纹理和姿态信息容易损失。

因此在 RT-DETRv2 原有多尺度特征基础上，探索引入浅层高分辨率特征。

重点考虑：

-   P2；
-   P3；
-   或与当前 RT-DETRv2 实际特征层对应的浅层高分辨率特征。

**这里暂时不强制规定必须存在 P2 层，最终根据所采用的 RT-DETRv2
开源实现调整。**

## 5.2 作用

高分辨率特征主要用于：

-   保留小目标边缘信息；
-   保留局部纹理；
-   提高小目标定位能力；
-   降低由于连续下采样造成的目标信息丢失。

## 5.3 主要验证指标

重点观察：

-   AP_S；
-   Recall；
-   mAP@0.5；
-   mAP@0.5:0.95。

------------------------------------------------------------------------

# 六、改进模块二：多尺度注意力机制

## 6.1 设计目的

密集笼养场景存在：

-   鸡群密集；
-   鸡体相互遮挡；
-   笼网遮挡；
-   光照不均；
-   背景纹理复杂。

因此加入轻量化多尺度注意力模块，使网络更加关注有效目标区域和具有判别力的特征。

## 6.2 模块设计原则

暂时不在方案阶段锁死具体注意力模块。

实际实现时可以根据 RT-DETRv2 的特征融合位置，选择一种轻量化方案，例如：

-   通道注意力；
-   空间注意力；
-   通道 + 空间混合注意力；
-   其他适合多尺度特征融合的轻量注意力结构。

最终只保留**一个经过实验验证的主要注意力模块**，避免项目复杂度过高。

## 6.3 主要验证指标

重点观察：

-   mAP；
-   Precision；
-   Recall；
-   遮挡场景检测效果；
-   参数量；
-   FLOPs；
-   FPS。

------------------------------------------------------------------------

# 七、改进模块三：细粒度特征学习

## 7.1 问题

死禽和休眠、趴卧状态的活禽可能存在明显外观相似性。

仅依靠检测分类损失，模型可能难以充分学习：

> "死禽"和"姿态异常但仍存活的鸡"

之间的细粒度差异。

## 7.2 方法

在训练阶段从检测网络中提取目标级特征，通过投影头映射到对比学习空间，然后使用
SupCon（Supervised Contrastive Learning）进行训练。

基本思路：

``` text
目标 RoI / Query Feature
        ↓
    Projection Head
        ↓
     特征向量 z
        ↓
      SupCon
```

使：

-   同类别样本特征更加接近；
-   不同类别样本特征具有更好的可分性。

## 7.3 注意

SupCon 不是独立的检测器，而是**训练辅助分支**。

训练完成后：

``` text
Projection Head
SupCon Loss
     ↓
   删除
```

推理阶段仍然只保留 RT-DETRv2 检测路径。

# 八、数据集方案

## 8.1 不建议只依赖当前小数据集

如果当前自建数据集规模较小，直接训练较大的 Transformer
检测模型容易出现：

-   过拟合；
-   验证集波动较大；
-   消融实验不稳定；
-   SupCon 正负样本不足；
-   论文实验说服力不足。

因此推荐采用：

> **"公开禽类数据辅助训练 + 自建死禽数据集作为核心任务数据"**

的方式。

------------------------------------------------------------------------

## 8.2 可考虑的公开数据

### 数据集 A：Poultry Detection for Counter

Roboflow 上存在一个较大的公开禽类检测数据集，约 **7,452
张图像**，包含多个禽类状态类别，其中包括：

-   Chicken；
-   Dead chicken；
-   Healthy Broiler；
-   lethargic chicken；
-   Sick Chicken；
-   Stressed chicken；
-   等。

该数据集可以作为本课题重点考察的数据源之一。

来源： Roboflow Universe --- poultry detection for counter

------------------------------------------------------------------------

### 数据集 B：Poultry Dataset

另一个公开数据集约 **7,454 张图像**，同样包含 `Dead chicken`
等类别，可用于辅助训练或补充死禽相关样本。

来源： Roboflow Universe --- poultry dataset

------------------------------------------------------------------------

### 数据集 C：Dead Chicken Detector

该数据集专门面向死禽检测，共 **86 张图像**，类别为：

``` text
dead_bird
```

规模较小，但任务相关性较高，可以用于补充死禽检测样本或进行外部测试。

------------------------------------------------------------------------

### 数据集 D：Chicken Detection and Tracking

该公开数据集包含鸡目标检测数据，公开版本最高达到数百张图像，可用于补充普通活禽样本。

它不适合作为死禽数据集直接使用，但可以作为活禽背景/负样本来源。

------------------------------------------------------------------------

### 数据集 E：PIO

2025/2026 年公开的 PIO
数据集面向真实商业和实验养殖环境中的肉鸡检测，包含：

-   1,487 张人工标注图像；
-   超过 327,289 个 broiler 实例；
-   单张图像最高可包含约 500 只鸡；
-   高密度养殖环境；
-   多种生长阶段。

该数据集的优势是**密集场景和大量目标**，因此特别适合辅助验证"小目标、密集遮挡"相关能力。

但它主要是活鸡检测数据，不能直接替代死禽数据集。

------------------------------------------------------------------------

# 九、推荐的数据使用方式

不要简单地把所有公开数据混在一起直接训练。

建议采用三个阶段：

## 阶段 1：公开数据辅助训练

利用公开禽类数据学习：

-   鸡体外观；
-   鸡体纹理；
-   鸡体姿态；
-   密集鸡群；
-   不同尺度目标。

------------------------------------------------------------------------

## 阶段 2：死禽数据集微调

使用自己的死禽数据集进行主要训练，使模型真正适应：

-   死禽；
-   笼养环境；
-   笼网；
-   密集遮挡；
-   死禽与休眠鸡的区别。

------------------------------------------------------------------------

## 阶段 3：独立测试

最终测试集尽量保持独立。

尤其不要把同一视频连续抽取的相邻帧随机分到训练集和测试集，否则容易造成数据泄漏。

推荐：

``` text
视频 A → Train
视频 B → Validation
视频 C → Test
```

而不是：

``` text
同一个视频
    ↓
随机抽帧
    ├→ Train
    ├→ Val
    └→ Test
```

------------------------------------------------------------------------

# 十、最终模型结构

``` text
                   RT-DETRv2
                       │
             ┌─────────┴─────────┐
             │                   │
       高分辨率特征增强       原有多尺度特征
       P2/P3（按实现调整）          │
             │                   │
             └─────────┬─────────┘
                       ↓
                多尺度注意力
                       ↓
                Feature Fusion
                       ↓
              RT-DETRv2 Encoder
                       ↓
              RT-DETRv2 Decoder
                       ↓
                 Detection Head
                       ↓
               Dead Chicken
                Detection
```

训练阶段：

``` text
                    Detection Feature
                           │
                 ┌─────────┴─────────┐
                 ↓                   ↓
            Detection Head      Projection Head
                 ↓                   ↓
               L_det               SupCon
                 └─────────┬─────────┘
                           ↓
                     L_total
```

# 十二、对比实验

可以选择：

-   YOLOv8；
-   YOLOv11；
-   RT-DETRv2；
-   MSF-DETR。

需要保证：

-   相同数据集；
-   尽量相同训练/验证/测试划分；
-   相同输入尺寸；
-   尽量统一训练策略；
-   使用相同评价指标。

**不要提前假设哪一个模型一定更好，最终以实验数据为依据。**

# 十五、实现原则

本课题必须遵循：

> **先跑通，再改进；先完成实验闭环，再增加复杂度。**

具体顺序：

1.  配置 RT-DETRv2；
2.  使用自己的数据集跑通 Baseline；
3.  保存 Baseline 指标；
4.  加入高分辨率特征；
5.  重新训练并记录结果；
6.  加入多尺度注意力；
7.  重新训练并记录结果；
8.  加入 SupCon；
9.  完成消融实验；
10. 与 YOLOv8、YOLOv11 等进行对比；
11. 完成可视化；
12. 根据硬件条件进行部署测试。

------------------------------------------------------------------------

# 十六、项目风险控制

如果 SupCon 实现难度较高：

> 优先保证 RT-DETRv2 + 高分辨率特征 + 注意力模块完整跑通。

如果 P2 接入导致网络结构修改过大：

> 可以只使用 P3 或其他浅层高分辨率特征，不强制加入 P2。

如果公开数据与自己的场景差异较大：

> 公开数据主要作为辅助训练数据，不直接作为最终测试集。

如果数据量仍然不足：

> 增加数据增强、交叉验证/多次重复实验，并严格避免视频帧泄漏。
